# N8N SalesFlow AI — Project Overview

**Date:** 2026-07-15
**Type:** Configuration-first automation/backend system
**Architecture:** Pipes-and-filters orchestration over a PostgreSQL command/state model

## Executive summary

The repository is a reproducible synthetic-local implementation of a policy-bound WhatsApp sales assistant. Seven n8n workflows orchestrate persisted work; PostgreSQL owns identity scope, consent, conversation state, authorization, idempotency, retries, Handoffs, deletion, audit, and release evidence. The local suite proves deterministic wiring and state transitions without claiming live Meta, LLM, CRM, compliance, or managed-infrastructure readiness.

## Project classification

- **Repository type:** single cohesive repository

- **Primary languages:** JSON, SQL/PLpgSQL, PowerShell, JavaScript
- **Architecture pattern:** thin workflows, durable command functions, deterministic policy gate, transactional outbox

## Key capabilities

- Authenticated, account-bound inbound ingestion with replay and sequence protection.
- Policy-grounded local turn completion that creates dispatch or Handoff work.
- Final authorization, leases/claims, bounded retry, and reconciliation states.
- Monotonic provider callback processing.
- Durable UTC Follow-Up and recovery scheduling.
- Human-Owned transfer and opt-out suppression.
- Versioned configuration, operational stop, deletion minimization, and release activation.
- One-command S01-S26, concurrency, import/export, secret-scan, and cleanup verification.

## Architecture highlights

- n8n never owns durable business state.
- External side effects are represented by unique persisted intents before adapter execution.
- Every customer send is authorized once at claim and rechecked immediately before the adapter.
- Workflow execution payload persistence is disabled.
- Source exports use only the approved native-node inventory.
- The current provider and Handoff adapters are deterministic synthetic nodes.

## Development overview
