## Critical directories

### `workflows/`

Reviewable n8n source exports. Filenames encode execution order by responsibility, not a mandatory sequential pipeline. Cross-workflow calls use stable IDs from `salesflow-wf-01` to `salesflow-wf-07`.

### `database/`

The business-state authority. Changing workflow routing without checking the called SQL function is unsafe because authorization, idempotency, retries, and terminal outcomes live here.

### `config/`

Synthetic-local typed inputs. Each non-account document is published per account by the test harness. Production values require approval and must not be inferred from these fixtures.

### `tests/`

The executable contract. `run.ps1` owns provisioning and cleanup; `runtime.sql` provides deterministic state assertions; the scenario JSON prevents silent test-set drift.

### `release/`

Pins container images, exact input hashes, canonical workflow hashes, approved node types, and the disabled live-promotion flag.

### `docs/` and `_bmad-output/`

`docs/` describes the observed brownfield baseline. `_bmad-output/planning-artifacts/` remains the product/design authority; `_bmad-output/implementation-artifacts/` records delivered scope and verification.
